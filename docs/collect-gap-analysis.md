# 数采模块 · 需求差距分析

> 对照《具身智能数据采集平台设计》第 2–6 章，只看主业务流程（采集 → 标注 → 审核 → 数据集），不涉及数据库设计和用户权限。
> 标记：✅ 已有　🔧 需调整　❌ 缺失

## 0. 结论速览

| 环节 | 现状 | 主要差距 |
|---|---|---|
| 采集 | 场景驱动（气密性/防护堵），SOP 6 步 + 驾驶舱 | 缺少「模式 → 机器臂 → 健康检查 → 标定 → 数据集 → 参数 → 预热」的准备阶段；缺校验结论与入库/重传；缺采集历史和导入入口 |
| 标注 | 切片 + 子任务名 + 自检 | 缺任务池/我的任务；一个切片只有「名称」，缺物体/语义/结果/关联四类字段；缺 AI 预切分 |
| 审核 | 6 维评分 + 问题标记 + 通过/打回 | 缺优先级池/SLA；决策只有 2 种（需要 4 种）；问题缺严重度；缺对比/一致性/质量统计 |
| 数据集 | 检索、版本、血缘、导出、预览 | 缺 5 种图谱视图；字典缺层级树和版本 |
| 看板 | 全局 KPI + 趋势 + 管线 | 缺按角色区分的个人工作台和公共图表 |

## 1. 采集主流程（第三章）

| 需求点 | 现状 | 标记 | 建议 |
|---|---|---|---|
| 采集模式选择 VR / UMI | 模式和场景绑死（qmd=VR，fhd=UMI） | 🔧 | 向导第一步改为「采集模式」，场景作为任务属性，两者解耦 |
| 选择目标机器臂（状态/电量/延迟/磁盘/最近标定，1–2 台，双臂配对） | 只能勾选场景设备列表，没有机器臂维度，也没有配对校验 | ❌ | 新增机器臂选择卡片；状态为离线/维护中时禁选；双臂只允许 Aloha-Dual 或 Franka-A+B |
| 设备健康检查（按模式区分的检查清单和阈值） | SOP 第 1 步「自检设备」只有一个按钮，返回通过/失败 | 🔧 | 改为逐项检查表（VR 9 项 / UMI 7 项）：显示数值和阈值，失败项给出处理建议，可「重新检查」 |
| 环境标定（内外参/基坐标/坐标对齐/力觉零点/时间同步<10ms） | SOP 第 2 步「空间标定」默认完成 | 🔧 | 拆成 5 个子项；7 天内标定过的可以复用，过期的必须重新标 |
| 选择/新建数据集（名称、机器臂、场景、物体清单） | 采集任务和数据集不关联，数据集在后续流水线里才生成 | ❌ | 向导里加「目标数据集」步骤（选已有的或快速新建），任务带上 dataset_id |
| 采集参数（帧率/分辨率/编码/音频/力觉/触觉/VR/UMI/命名/失败自动重录/语言指令） | 第 2 步只能看到设备通道和采样率，无法配置 | 🔧 | 改为参数表单，默认值取系统配置；底部显示预计每小时体量 |
| 任务描述（任务名/语言指令/关键物体） | 只有名称、备注 | 🔧 | 增加语言指令、关键物体，供标注语义复用 |
| 预热 1–2 个 Episode（不计量 + 回放检查） | 无 | ❌ | 在 SOP「复位」和「采集」之间加一个预热步骤：录了之后可以回放，确认后才进入正式采集 |
| 开始录制 3 秒倒计时 | 无 | ❌ | 驾驶舱开始时加倒计时遮罩 |
| 录制界面（多视角 + 手柄/夹爪 + 关节 + 末端 XYZ + 力觉曲线） | 驾驶舱 6 路视频 + 3D 场景 + 双手遥测（夹爪开度、法向力） | ✅/🔧 | 按模式切换遥测面板：VR 显示手柄 L/R 和关节角，UMI 显示握力/6DoF/触觉 12 通道/温度；加一个 Fx/Fy/Fz 曲线 |
| 录制参数栏（fps/分辨率/码率 GB/h/磁盘剩余） | 只有「30 FPS · 1080P · 0 丢包」 | 🔧 | 补上体量速率和磁盘剩余 |
| 操作：暂停/停止/标记事件/备注/回退到上一标记/标记失败 | 有结束、标记、备注、标记失败，暂停在抽屉里 | 🔧 | 「暂停」移进驾驶舱；新增「回退到上一标记」（丢弃标记之后录的内容）；标记改为带时间点的事件列表 |
| 实时质量反馈（漂移/追踪丢失/加速度/遮挡/力觉超限/帧率/同步漂移） | 实时监控页有掉帧和同步误差告警，驾驶舱里看不到 | 🔧 | 驾驶舱顶部加质量提示条，超过阈值时变红，并在时间轴上打点 |
| 停止后「采集结果」对话框 | 结束后直接后台质检 | ❌ | 停止后弹窗：时长/帧数/体量/事件数，选择「保存 / 重录 / 标记失败」 |
| 自动校验（7 项）+ 人工回放校验 → 通过 / 失败 / 异常带警告入库 | SOP 第 5 步「数据质检」只给一个结果；Episode 有完整性/同步/评分 | 🔧 | 改为校验报告：7 项自动结果 + 回放勾选任务完成度，最终给出三种结论之一 |
| 入库（上传/转码/元数据/缩略图/去重/通知标注员）+ 断网重传 3 次 → 待重传队列 | SOP 第 6 步「归档上传」一步完成 | 🔧 | 显示入库子进度；失败的进「待重传」，可以手动重传 |
| 断点续录 / 离线缓存 | 暂停/继续可用，「重新开启」可用 | ✅/🔧 | 中断后再次进入时提示「从第 N 个 Episode 继续」 |
| 多机协同（双臂同步、共享 dataset_id） | 无 | ❌ | 依赖机器臂配对；驾驶舱分左右臂显示 |
| 采集首页（4 KPI：今日/本月/有效率/设备利用率；快速开始；任务表；机器臂状态卡） | 采集任务页只有一张任务表 | 🔧 | 任务页顶部加 KPI 行和快速开始卡（VR / UMI / 视频上传 / LeRobot 导入），右侧放机器臂状态卡 |
| 采集历史（按模式筛选；状态：已入库/异常/失败） | 无独立页面，Episode 只能在任务抽屉里看 | ❌ | 新增「采集历史」Tab，以 Episode 为粒度汇总 |
| 视频上传 / 动捕采集 / LeRobot 导入 | 无 | ❌ | 先做视频上传和 LeRobot 导入弹窗（选文件 → 校验 → 选数据集 → 入库）；动捕放到后面 |

## 2. 标注流程（第四章）

| 需求点 | 现状 | 标记 | 建议 |
|---|---|---|---|
| 任务池（数据集/模式/时长/难度/预计耗时/积分；批量领取 1–10；预览） | 左侧 ClipList 直接列出全部数据 | ❌ | 标注页分「任务池 / 我的任务」两个 Tab，领取后才能进入工作台 |
| 我的任务（待处理/进行中/已提交/已通过/已驳回） | ClipStatus：todo/rejected/submitted/approved | 🔧 | 补一个「进行中」状态，按状态分组筛选 |
| 时间切分：多机位 + 传感器曲线、拖拽边界、缩放、删除/合并/插入、快捷键 | VideoWall + SliceTimeline，可以切分/合并/删除/撤销，有快捷键 | ✅/🔧 | 补时间轴缩放、拖拽边界、传感器曲线行；快捷键对齐需求（A/D/M、Shift±5s、Ctrl+S） |
| AI 预切分 | 无（流水线写明暂不用 AI） | ❌ | 先做成「按规则预切分」（力觉/夹爪突变点）按钮，接口留给后面接 AI |
| 6 类标注：时间 / 动作类型（树形字典，基础/复合/异常，拼音搜索）/ 物体（主+副）/ 语义描述 / 结果 success+失败原因 / 关联 | Seg 只有 {s,e,n}，n 就是子任务名 | 🔧（核心） | Seg 增加 action、objMain、objSub[]、desc、result、failReason、links；右侧加「标注详情」面板 |
| 质量自检（连续/不重叠/必填/字典有效/语义 5–200 字/区间 ≥3） | 有覆盖率、阻断/预警、规则清单 | ✅/🔧 | 加上必填、字典有效、语义字数、≥3 区间这几条规则 |
| 提交审核（提交说明 + 二次确认；驳回后改完重提） | 可以提交/撤回，显示驳回原因 | 🔧 | 提交时弹窗填说明；驳回的数据定位到有问题的切片 |
| 布局：左视频 / 中时间轴 + 详情 + 字典 / 右标注列表 | 视频 + 时间轴 + 切片表 | 🔧 | 跟着 6 类标注的改造一起调整 |

## 3. 审核流程（第五章）

| 需求点 | 现状 | 标记 | 建议 |
|---|---|---|---|
| 待审核池（P0/P1/P2 + SLA 1h/24h/48h，批量领取 1–50） | 「待审质检任务」列表，没有优先级 | ❌ | 加优先级标签和 SLA 倒计时（超时标红），支持批量领取 |
| 我的审核 | 无 | ❌ | 和标注一样分两个 Tab |
| 6 维度评分 + 综合分 | 已有（每项 5 星） | ✅/🔧 | 需求是 10 分制，通过标准是「≥5 个维度 ≥8 分」，改成按阈值自动给出建议结论 |
| 问题标记（区间/类型/描述/严重度：致命/一般/建议） | 有切片级类型和描述 | 🔧 | 增加严重度；支持在切片内选子区间 |
| 决策：通过 / 建议修改后通过 / 驳回（意见 + 模板）/ 退回重做 | 只有「通过」「打回重标」 | 🔧 | 补齐成 4 种；驳回可选模板；退回重做的数据回到任务池 |
| 标注对比（多版本） | 无 | ❌ | 两条时间轴上下对照，差异处高亮 |
| 一致性报告 / 质量统计（今日审核、通过率、驳回率、平均分、趋势、标注员绩效、常见驳回原因） | 无 | ❌ | 在审核页加「质量统计」Tab |
| 审核员编辑字典 | 有「标准语义字典管理」 | ✅ | 和标注的子任务字典合并成一套（见第 4 节） |

## 6. 优先级与实施方案

**P0 · 主流程跑通（建议先做）**
1. 采集准备阶段重构：向导改为 模式 → 机器臂 → 数据集 → 参数/任务描述；SOP 改为 健康检查（逐项）→ 环境标定（5 项）→ 预热 → 正式采集 → 校验 → 入库。
2. 驾驶舱：3 秒倒计时、回退到上一标记、实时质量提示条、停止后的「采集结果」对话框。
3. 校验报告（自动 7 项 + 人工回放）→ 三种结论；入库进度和待重传队列。
4. 标注：Seg 扩展为 6 类字段 + 标注详情面板 + 补齐自检规则。
5. 审核：4 种决策、10 分制、问题严重度。

**P1 · 体验与协作**
6. 采集页 KPI、快速开始、机器臂状态卡；新增「采集历史」Tab。
7. 标注/审核加任务池和我的任务（领取机制）；审核加优先级和 SLA。
8. 统一字典（树形 + 版本）；时间轴缩放、拖拽、传感器曲线；规则预切分。
9. 视频上传、LeRobot 导入弹窗。

**P2 · 分析与可视化**
10. 审核质量统计、标注对比、一致性报告。
11. 数据集图谱 5 种视图、标注日历。
12. 个人工作台和公共图表；多机协同、动捕采集。

**数据结构改动要点（前端 mock）**：Task 加 mode / arms[] / datasetId / params / langInstr / objects / warmup / checks[] / calib[]；Episode 加 verdict（ok/warn/fail）/ events[] / upload（done/retry/queued）；Seg 加 action / objMain / objSub / desc / result / failReason；Review 加 priority / sla / decision（4 种）/ issues[].severity。
